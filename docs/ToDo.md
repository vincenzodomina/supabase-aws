The reviewed baseline has eight core Fargate tasks totaling 2 vCPU and 5 GiB, with optional Studio/meta adding one task and an internal ALB. The rendered template is 112,057 bytes with 92 declared resources, including 36 security groups/rules. The existing template/task-size check passed; the S3 deployment path accommodates the template within [CloudFormation quotas](https://docs.aws.amazon.com/AWSCloudFormation/latest/UserGuide/cloudformation-limits.html).

Preserve independent core services, paired Studio/meta, two-replica availability, RDS Multi-AZ, and the single-stack deployment unless requirements justify a change. Cloud Map avoids the additional proxy resources recommended for [Service Connect](https://docs.aws.amazon.com/AmazonECS/latest/developerguide/service-connect-concepts-deploy.html). Certificate/readiness helpers share existing task allocations; removing a helper alone does not reduce configured Fargate capacity.

Real RDS compatibility, failover, replacement under traffic, and upgrade/recovery remain separately approved manual AWS acceptance work (NG-03). Local Docker/Moto checks cannot prove them. The existing migration boundary must remain explicit: container rollback does not reverse committed database migrations. [AWS schema compatibility guidance](https://docs.aws.amazon.com/wellarchitected/latest/devops-guidance/dl.ads.5-ensure-backwards-compatibility-for-data-store-and-schema-changes.html).
